# Executing 阶段 — 按计划实现

## 阶段目标
严格按照 `plan.md` 中的 checkbox 顺序实现功能，并遵循 TDD 铁律：写测试 → 实现 → 重构。支持断点恢复。

## 输入条件
- `plan.md` 存在且用户已确认。
- 用户明确说“开始执行”、“实现”或状态检测显示计划未完成。

## 核心流程

### 1. 读取当前进度
- 打开 `openspec/changes/<change-name>/plan.md`
- 找到第一个未勾选 `- [ ]` 的任务项（按顺序）。
- 向用户报告：“当前进度：已完成 X/Y 项，下一个任务是：[任务描述]”

### 2. 执行单个任务（原子操作）
对于每个任务，执行以下子步骤：

- **写测试**：为将要实现的功能编写失败的测试（单元/集成/E2E）。
- **写实现**：使测试通过的最小代码。
- **重构**：优化代码结构，确保测试仍通过。
- **更新 checkbox**：将对应的 `- [ ]` 改为 `- [x]`，并保存文件。

### 3. 遇到障碍或需细化时
如果当前任务过于复杂，可以：
- 调用 Superpowers `writing-plans` 生成更细粒度的子计划（存放在 `docs/superpowers/plans/`）。
- 或者手动将当前任务拆分为多个子 checkbox 更新到 `plan.md`。

### 4. 提交代码（建议）
每完成一个逻辑单元（如一个接口或一个组件），执行：
```bash
git add .
git commit -m "feat: <描述> 完成"
```

### 5. 循环直到所有任务完成
- 重复步骤 2-4。
- 如果遇到需要修改规格的情况（用户提出新需求），**暂停执行**并提示：“当前需求变更，请使用 `amend` 修订计划后再继续”。

### 6. 完成提示
当所有 checkbox 都勾选后：
> “所有实现任务已完成。请使用 `archive` 归档此变更。”

## 断点恢复
- 若对话中断，AI 重新进入时，先读取 `plan.md` 并定位到第一个未完成项，继续执行。
- 不要从头开始。

## 禁止行为
- ❌ 跳过测试直接写实现（除非项目无测试框架，此时应记录并提示）
- ❌ 修改规格文档（`spec.md`, `proposal.md`, `design.md`）——如果需要修改，应提示使用 `amend`
- ❌ 在未完成所有任务时进入 `archive`
